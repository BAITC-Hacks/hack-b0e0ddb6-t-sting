# Council implementation plan

> Execute the supplied, approved feature plan with independent implementation tasks and a final integration review. User authorization covers autonomous implementation and local verification.

**Goal:** Complete the review → council → verified amendment/package → new review flow.

**Architecture:** The existing simulation engine owns every number and admissibility decision. Pure council modules produce briefs and votes; OpenAI supplies bounded, checked prose. PostgreSQL stores an append-only event history exposed through replayable SSE; React renders that history and applies engine-generated plans.

**Tech stack:** Existing NestJS, TypeORM, PostgreSQL, RxJS, React, Vite, Vitest and Playwright. Native server-side fetch for OpenAI.

**Spec:** [Supplied feature plan](../specs/2026-09-23-council.md).

## Constraints and integration decisions

- OpenAI is the only provider for both the analyst and council. An empty server-side `OPENAI_API_KEY` selects functional deterministic offline mode.
- Preserve seven members, debate, bounded chair tools, rejected package attempts, votes, persistence, streaming/replay and application of amendments.
- Full-precision engine values drive decisions; presentation rounds only at the edge.
- Reuse `apps/api/src/council/types.ts` as the web/API event contract. SSE IDs are one-based event offsets; reconnect skips IDs already received.
- Existing isolated worktree, branch `codex/ai-council`, fetched from `origin/main`.
- No merge, deployment, or live-provider claim. No key required for verification.
- Meaningful 100% per-file application line/branch coverage remains enforced.

## Tasks

- [x] Domain: roles, metrics, candidates, briefs, package validation, votes and numerical regression tests. Boundary: `prepareCouncil(plan)`, `evaluatePackage(context, ids)`, `votesFor(context, evaluation)`.
- [x] Agents: OpenAI adapter, deputy fact/ID checking and isolated fallback, parallel rounds, four-step chair tool loop, deterministic offline protocol. Boundary: async runner `(plan, emit)`, with `emit` awaited for durable event ordering.
- [x] Sessions: TypeORM entity/migration, persistence before publication, late/reconnecting SSE subscribers, invalid plan/unknown ID/database failure/restart handling, Nest wiring.
- [x] Interface: supplied K0–K6 design adapted to existing UI, session resume/replay, map and metric impacts, package log, votes/protocol, apply action triggering a fresh review.
- [x] Verification/documentation: complete unit coverage, lint/type/build, live proxy/SSE/PostgreSQL smoke, browser core flow and responsive checks, OpenAI setup, limitations and numerical discrepancy notes.

## Review focus

1. A provider failure affects only its member; unsupported numbers and IDs never reach verified prose.
2. Conflicting or over-budget packages appear as rejected attempts and cannot enter recommendations.
3. Concurrent events are persisted in order and reconnect never duplicates or loses events.
4. Process restart marks unfinished sessions interrupted; saved completed sessions remain replayable.
5. Applying a verified amendment changes the actual plan and initiates a new engine review.

For each task, write behavior tests before implementation, verify the failure, implement, then run the scoped tests. Before each logical commit run the complete coverage suite; before completion run `npm run check`, `diff -qr .agents/skills .claude/skills`, live smoke and the council browser flow.
